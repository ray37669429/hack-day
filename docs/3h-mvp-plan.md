# 3 小時 MVP 開發評估：多人 × Claude Code × Codex

> 狀態：建議方案。範圍依 [farmer-ux-agents.md](farmer-ux-agents.md) 第 6 節的 MVP 決定。

## 結論

**做得完，但有三個前提**，缺一個就要砍範圍：

1. **開工前的準備不算在 3 小時內**：每台電腦能跑專案、AI 工具已登入、API 金鑰到位、遮蔽樣本與正確答案準備好。這些現場做至少吃掉 30–45 分鐘。
2. **先定好資料格式再分頭寫**：前 20 分鐘由一人寫好資料模型（Ontology）與一份假案例，之後每個人都對著同一份格式開發，最後才接得起來。
3. **AI 擷取要有備案**：視覺 AI 讀謄本不穩時，改用人工輸入的「正確答案」當擷取結果，流程照樣能展示。

已經完成、可以省下時間的部分：同意書 Word 產生器（`tools/make_agreement.py`，版面已對過紙本）、規則文件、git 與協作設定。

## 範圍分三層

| 層級 | 內容 | 完成機率 |
| --- | --- | --- |
| **一定要有**（沒有就不能展示） | 一個案例從「擷取結果」→ 協助者確認 → 產出同意書 Word（正式或草稿）；農民端回答 3 題的手機網頁 | 高 |
| **應該要有** | 語音：預錄題目＋國語語音回答（見 [voice-design.md](voice-design.md)，先做朗讀再做辨識）；手機拍照上傳＋照片品質檢查；視覺 AI 真的讀謄本；分派規則與「我不確定」轉協助者；Excel 核對表 | 中 |
| **有空再做**（先砍） | Excel 改完讀回系統；集團土地清單 Excel（範本還沒拿到）；第二組未調校案例；與舊清單比對（目前沒有舊清單資料） | 低 |

## 技術選擇（為了 3 小時，選最少的東西）

| 項目 | 選擇 | 原因 |
| --- | --- | --- |
| 語言 | Python 3.10 以上 | Word 產生器已用 Python；Excel、AI、網頁都有成熟套件 |
| 網頁 | FastAPI + 純 HTML 模板 | 大字大按鈕自己寫 CSS 最好控制；手機用 `<input type="file" capture>` 就能拍照 |
| 資料儲存 | 每個案例一個 JSON 檔（放 `data/output/`） | 不用架資料庫，出錯時直接打開看 |
| 資料模型 | Pydantic | 同一份定義可以驗證輸入、要求 AI 照格式輸出、產生文件 |
| AI | 視覺 LLM API（金鑰放 `.env`） | 只用遮蔽樣本，可以用雲端服務 |
| 語音合成 | Qwen3 TTS（`qwen3-tts-flash`），開工前產生固定語句音檔 | 現場不依賴網路即時合成 |
| Excel / Word | openpyxl / python-docx | Word 已完成 |

## 模組切分（每人負責不同資料夾，避免互相衝突）

```text
app/
  models.py      ← 資料格式（Ontology）。只有負責人能改，其他人要改先講
  store.py       ← 讀寫案例 JSON
  actions.py     ← 確認、退回、補欄位等動作與送出條件
  agents/
    intake.py    ← ① 收件：照片品質檢查
    extract.py   ← ② 擷取：視覺 AI → 待確認主張（含備案）
    check.py     ← ③ 核對：地號格式、持分、單位等規則
    triage.py    ← ④ 分派：題目給農民或協助者
    document.py  ← ⑤ 文件：呼叫 tools/make_agreement.py
  review_excel.py← 協助者核對表 Excel
  web/           ← 農民端手機網頁（FastAPI 路由 + HTML）
    voice.js     ← 語音：朗讀、辨識、關鍵詞比對、唸回確認
    audio/       ← 預錄題目音檔（國語、台語）
tests/fixtures/C00.json ← 假案例，所有人共用
```

每個模組都能**單獨**拿假案例跑，不用等別人做完。

## 分工建議

| 工作線 | 負責內容 | 適合誰 | 搭配工具 |
| --- | --- | --- | --- |
| **L1 核心與整合** | `models.py`、`store.py`、`actions.py`、`document.py`、最後串接 | 最熟程式的人 | Claude Code 或 Codex |
| **L2 AI 擷取** | `extract.py`、`intake.py`、備案 | 第二位會寫程式的人 | 另一個工具 |
| **L3 農民端網頁＋語音** | `web/` 四個畫面、`voice.js`（朗讀 → 語音回答 → 唸回確認） | 任何人＋AI 工具 | Claude Code 或 Codex |
| **L4 協助者端** | `review_excel.py`、`check.py`、`triage.py` | 任何人＋AI 工具 | Claude Code 或 Codex |
| **資料與驗收**（不寫程式） | 遮蔽樣本、正確答案、驗證規則、測試、計時 | 地政隊員 | — |
| **產品與展示**（不寫程式） | 校對台語句子、扮演農民與協助者試用、砍範圍、展示腳本 | 永錫 | — |

人手不夠時，L3 和 L4 由同一人做，先做 L3。L3 工作量最大（約 90 分鐘含語音），有第五個人時，語音可以獨立成一條工作線。

## 時間表（180 分鐘）

| 時間 | 做什麼 | 產出 / 檢查點 |
| --- | --- | --- |
| **開工前** | 環境、金鑰、樣本、AI 工具登入（見下方清單） | 每個人能跑 `python tools/make_agreement.py` |
| **0:00–0:20** | L1 寫好 `models.py` 與假案例 `C00.json`，推上 `main`。其他人讀 AGENTS.md、開分支。地政隊員整理正確答案 | 資料格式凍結 |
| **0:20–0:50** | 四條工作線平行開發 | 第一次合併：各模組能用假案例跑 |
| **0:50–1:20** | 繼續開發 | 第二次合併 |
| **1:20–1:50** | 繼續開發；**1:50 停止新功能** | 第三次合併 |
| **1:50–2:20** | 整合：用真正的遮蔽樣本從頭跑到尾，修串接問題 | 一個案例跑通 |
| **2:20–2:40** | 永錫扮演農民與協助者試用；地政隊員對答案、計時 | 填 `docs/acceptance-log.md` |
| **2:40–3:00** | 只修影響展示的問題，排練 3 分鐘展示 | 可展示版本 |

**砍範圍的時機**：1:20 檢查點時，「一定要有」還沒完成，就停掉所有「應該要有」的工作，全員支援。

## Claude Code × Codex 多人協作規則

1. **共用一份規則**：兩種工具都讀 `AGENTS.md`（Claude Code 透過 `CLAUDE.md` 引用），已設定好。
2. **一人一分支、一人一資料夾**：`feat/<名字>-<模組>`。叫 AI 只改自己負責的資料夾。
3. **資料格式凍結**：`app/models.py` 只有 L1 能改。其他人需要新欄位時告訴 L1，不要讓 AI 自己加。
4. **套件清單事先定好**：`requirements.txt` 在開工前一次寫好，開發中不讓 AI 隨意新增套件，避免合併衝突。
5. **每個模組附可以單獨跑的測試**：AI 寫完能自己驗證，不用等整合。
6. **小步合併**：每 30 分鐘合併一次，PR 由 L1 合。不要最後才一次合。
7. **交叉檢查**：整合時，可以讓 Claude Code 看 Codex 寫的 PR，反過來也一樣，抓明顯錯誤。只在整合階段做，開發中不花時間。
8. **卡住 15 分鐘就換方法**：不要和 AI 反覆拉扯。改用備案或縮小範圍，並告訴 L1。
9. **給 AI 的任務要短而具體**：每條工作線事先準備一段任務說明（要做什麼、輸入輸出格式、不能做什麼），開工直接貼給 AI。

## 開工前清單

- [ ] 每人 clone repo，裝好 Python 3.10 以上，`pip install -r requirements.txt` 成功
- [ ] 每人 Claude Code 或 Codex 已登入，能在專案資料夾執行
- [ ] 視覺 AI 的 API 金鑰放進每人的 `.env`（不要 commit）
- [ ] 假謄本與正確答案已在 `data/samples/fake-transcripts/`（虛構資料）；地政隊員檢查內容像不像真的謄本
- [ ] 申請阿里雲 DashScope 金鑰（閩南語需北京區），執行 `python tools/gen_tts.py` 產生音檔
- [ ] 台語句子（`web/audio/prompts.json`）請母語者校對
- [ ] 準備 HTTPS 通道（cloudflared 或 ngrok），手機才能用麥克風
- [ ] 確認手機和筆電在同一個網路，手機打得開筆電上的網頁（會場 Wi-Fi 若阻擋，改用筆電瀏覽器的手機模式展示）
- [ ] Windows 電腦設定 `PYTHONIOENCODING=utf-8`，避免中文檔名和輸出變亂碼
- [ ] 每條工作線的 AI 任務說明寫好

## 主要風險

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 現場才裝環境 | 吃掉 30 分鐘以上 | 開工前清單全部完成 |
| 沒有遮蔽樣本或正確答案 | 擷取無法驗證 | 地政隊員事先準備；最差情況用虛構謄本 |
| 視覺 AI 讀錯或很慢 | 展示失敗 | 備案：直接載入正確答案當擷取結果，並在展示時說明 |
| 多人改同一個檔案 | 合併衝突 | 分資料夾、凍結 `models.py` 與 `requirements.txt` |
| 最後才整合 | 接不起來 | 每 30 分鐘合併；所有人對同一份假案例開發 |
| 會場網路擋手機連線 | 無法用手機展示 | 筆電瀏覽器手機模式 |
| 手機用 http 連線時麥克風被擋 | 語音回答無法展示 | 用 HTTPS 通道，或在筆電 Chrome（localhost）展示語音 |
| Qwen3 TTS 帳號區域不支援閩南語 | 沒有台語朗讀 | 先用國語音檔；開工前確認區域 |
| 長輩講台語，國語辨識聽不懂 | 語音回答失敗 | 聽不懂兩次自動改用按鈕；展示時說明台語辨識是下一步 |
| AI 工具自行擴大範圍 | 時間失控 | AGENTS.md 已寫明「不在 MVP 範圍不要加」 |
