# 虛構謄本測試圖（黑客松測試用）

> **全部是虛構資料，不是正式謄本，不具任何效力。**
> 每頁都有斜向浮水印「測試用虛構資料　非正式謄本」與頁尾聲明；沒有印章、簽名、條碼或 QR code。
> 地名（範例縣、試驗鄉、示範段等）、機關（範例地政事務所）、人名（農民A/B/C）、身分證號（已遮蔽）都是編的。

用途：測試「擷取 agent」（讀謄本填欄位）和「拍照品質檢查 agent」。

## 案例

| 案例 | 測什麼 | 重點 |
| --- | --- | --- |
| C01 正常 | 1 位所有權人（農民A）、2 筆土地，各一頁 | 基本擷取；地號 `0123-0004`、`0123-0005` 要保留前導零 |
| C02 共有 | 1 筆土地由農民A、農民B 各持分 `2分之1` | 有小段（測試段北小段）；所有權部跨頁（續次頁／接前頁）；兩人不可合併 |
| C03 易錯 | 示範段與示範一段**地號相同**（都是 `0005-0001`） | 段名相似不可混淆；面積 `1,000.05`、`2,499.95` 接近進位邊界；第 2 頁權利範圍被污損，答案是「待確認」 |

## 每個資料夾內容

- `page1.png`、`page2.png`：乾淨版（A4 直式，約 160 dpi）。
- `photo_page1.jpg`：模擬手機翻拍第 1 頁（傾斜、透視、光線不均、輕微模糊），應**通過**品質檢查。
- `photo_page1_bad.jpg`（只有 C03）：太暗＋嚴重模糊＋右側被切掉，應**不通過**。
- `answer.json`：標準答案。

## answer.json 欄位

- `parcels`：一筆土地一筆資料。`parcel_id` 只是本檔內的代號；土地主鍵是 縣市＋鄉鎮＋段＋小段＋地號。面積分 `area_raw`（謄本原樣，含千分位）、`area_unit`、`area_m2`（去千分位的文字），不做公頃換算。
- `ownerships`：一筆持分一筆資料（對應 Ontology 的「持分」物件）。`share_raw` 是原文，`share_num`／`share_den` 是分子／分母。
- `pending`：看不清、不可猜的欄位；對應的值一律填 `"待確認"`。
- `expected_quality`：每張圖預期 `pass` 或 `fail`。
- 地號、面積都存成文字。

## 重新產生

```bash
PYTHONIOENCODING=utf-8 python tools/make_fake_transcript.py
```

需要 Pillow 與 Windows 內建繁中字型（細明體／微軟正黑體／標楷體擇一）。
乾淨版每次產生都一樣；翻拍圖的雜訊是隨機的，每次會有些微差異，但不影響預期結果。
